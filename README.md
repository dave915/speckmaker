# Speck

디자이너와 개발자가 HTML 목업을 함께 리뷰하는 작업 공간입니다.

## 기능

- 프로젝트 생성과 프로젝트별 HTML 업로드: 파일당 5MB, 한 번에 최대 10개 파일
- HTML 탭 자동 감지와 별도 프레임 표시: 파일당 최대 12개 화면
- 캔버스 이동, 확대·축소(8–200%), 전체 화면 맞춤, 트랙패드 확대
- 기준 화면 높이와 함께 저장되는 핀 댓글, 답글, 해결·다시 열기
- 프로젝트 채팅, 참여자 표시, 공유 커서: 약 1.8초 주기로 서버 동기화
- D1 데이터베이스에 프로젝트·댓글·참여 정보 저장, R2에 HTML 원본 저장
- 모바일 프로젝트 메뉴, 접었다 펼치는 코멘트 패널

첫 접속에는 Luma 샘플 프로젝트와 사용 가이드 댓글 3개가 준비됩니다. 샘플의 대시보드 수치는 예시입니다.

## HTML 지원 범위

ARIA `role="tab"`, Bootstrap 탭, `data-tab`, 일반적인 탭 버튼 클래스와 `onclick` 기반 버튼을 감지합니다. 각각의 샌드박스 iframe에서 해당 탭을 활성화합니다. 자동 감지가 맞지 않으면 업로드 화면에서 한 화면으로 합칠 수 있습니다. 사용자 파일을 사이트 DOM에 직접 삽입하지 않으며 iframe은 `allow-scripts`만 허용합니다. iframe에 같은 출처 권한, 팝업, 폼 제출, 상위 페이지 탐색 권한은 부여하지 않습니다.

CSS, 이미지, JavaScript가 포함된 단일 HTML을 권장합니다. 로컬의 별도 파일 및 ZIP 업로드는 지원하지 않습니다. JavaScript 실행 후에만 생성되는 탭, 임의의 사용자 정의 탭 시스템, 프레임워크 라우터를 통한 페이지 전환은 자동 분리가 보장되지 않습니다. 프레임 폭은 740px이며 높이는 콘텐츠에 맞춰 자동으로 늘어납니다(최소 880px, 최대 20,000px). 내부 스크롤을 사용하는 앱의 스크롤 동작은 유지합니다. 기본 상태에서 버튼·링크·입력 폼을 바로 사용할 수 있고, H로 이동 모드, C로 코멘트 모드를 켭니다.

## 협업과 접근

프로젝트 링크에는 프로젝트 식별자가 포함됩니다. 사이트에 접근할 수 있는 사용자는 팀 워크스페이스의 모든 프로젝트를 볼 수 있습니다. 프로젝트별 역할, 초대 이메일, 사용자 인증 시스템은 별도로 구현하지 않았습니다. 배포 환경의 Sites 접근 제어가 적용되며 최초 배포는 비공개입니다. 실제 팀원과 사용하려면 사이트의 대상 사용자 범위를 설정해야 합니다.

프로필 이름·색상만 기기에 보관하며, 프로젝트와 업로드 및 대화 데이터의 원본은 서버에 저장됩니다. 실시간 동기화는 WebSocket 대신 짧은 주기 폴링을 사용합니다.

```sh

```

## 확인한 흐름

실제 브라우저 두 세션에서 프로젝트 생성 → HTML 업로드 → 세 탭의 서로 다른 내용 확인 → 핀 댓글 작성 → 다른 세션 동기화 → 답글 → 해결 처리 → 채팅 수신 → 새로고침 후 데이터 유지까지 확인했습니다. 확대 후 핀 크기가 27px로 유지되고 비율 좌표가 유지되는 것을 확인했습니다. 390px 모바일 화면의 가로 넘침, 프로젝트 메뉴와 코멘트 접근도 확인했습니다.

높이 자동 조절 수정 후에는 1,860px 목업의 프레임 높이·문서 높이·푸터 끝 좌표가 일치하는지 확인했습니다. 기본 클릭으로 콘텐츠가 2,280px, 2,700px로 늘어나는 동작, 입력 폼, 탭 전환, 목업 위 휠 이동·Ctrl 휠 확대, 880px 아래에 남긴 코멘트의 위치 유지도 검증했습니다.


## Ollama로 HTML 부분 수정

상단의 **AI 수정**에서 `http://localhost:11434`에 연결하고 도구 호출을 지원하는 모델을 선택합니다. 브라우저가 Ollama의 `/api/chat`으로 직접 요청하며 서버 중계는 사용하지 않습니다. `/api/tags`에서 모델을 불러오고 `/api/show`로 도구 지원과 문맥 용량을 확인합니다.

전체 HTML은 브라우저의 작업 복사본에 보관합니다. 모델에는 파일 정보와 요청을 먼저 전달하고, 모델이 호출한 도구를 통해 필요한 코드 조각만 돌려줍니다. 수정한 내용을 전체 HTML로 다시 생성하게 하지 않습니다.

| 도구 | 역할 |
| --- | --- |
| `list_files` | 현재 목업의 경로·크기·작업본 변경 번호 확인 |
| `search_file` | 일반 문자열 검색과 주변 코드 확인 |
| `read_file` | 문자 위치 기준으로 필요한 범위 읽기 |
| `replace_text` | 정확히 한 곳에 일치하는 코드만 부분 교체 |
| `validate_preview` | 탭 렌더링, 실행 오류, 선택적 클릭·입력·CSS/문구 검사 |
| `get_diff` | 성공한 부분 수정 내역 확인 |

현재 선택한 HTML은 가상 경로 `mockup.html`로만 접근합니다. 호스트 파일 시스템, 터미널 실행, 모델이 지정한 URL을 가져오는 도구는 제공하지 않습니다. 수정은 임시 작업본에 누적되며, **적용하고 이력 저장**을 눌러야 공유 목업이 바뀝니다. 적용 전에는 현재 목업과 수정안을 비교하고 각 부분 수정의 전후 코드를 볼 수 있습니다.

### 큰 파일과 실행 범위

AI 전용 48KB 제한을 제거했습니다. 기존 목업 업로드·저장 한도는 5MB입니다. 파일이 커도 한 번에 읽는 범위를 제한해 모델에 전달합니다. 압축된 한 줄 HTML도 문자 위치와 검색으로 편집합니다.

- 한 번의 읽기: 최대 4,000자, 모델 문맥에 따라 더 작게 조정
- 한 번의 교체: 기존/새 코드 각각 최대 12,000자, 정확히 한 곳에만 적용
- 실행: 모델 응답 최대 24회, 도구 최대 80회, 최대 10분, 사용자가 언제든 중단 가능
- 문맥: 모델 지원 범위 안에서 최대 32,768 토큰으로 요청하고, UTF-8 바이트를 보수적 상한으로 사용해 출력 공간을 확보
- 오래된 도구 응답은 호출과 결과를 함께 정리합니다. 작업본은 유지하며 필요한 코드는 다시 읽습니다.

오래된 작업본을 대상으로 한 교체, 여러 위치에 일치하는 교체, 잘린 모델 응답은 적용하지 않습니다. 도구 오류와 새 미리보기 오류를 모델에 전달해 재수정하도록 하고, 완료 문구와 관계없이 최종 작업본을 다시 검사합니다.

### 미리보기 검사의 범위

검사는 별도의 `sandbox="allow-scripts"` iframe에서 수행합니다. 원본 탭을 확인하고 새 실행 오류를 비교하며, 모델이 지정한 클릭/입력 및 CSS·문구 조건을 검사할 수 있습니다. 검사를 완료하지 못한 화면은 통과로 처리하지 않습니다. 검사 중에는 네트워크 API 요청과 폼 제출을 차단합니다.

이 검사는 DOM과 실행 결과에 대한 제한된 검사이며, 모든 화면 크기·접근성·외부 서버 동작·장시간 비동기 동작을 보증하는 전체 테스트는 아닙니다. 시각적인 최종 결과는 사용자가 수정안 미리보기에서 확인합니다.

### Ollama 연결

배포된 사이트에서 로컬 Ollama에 접근하려면 해당 출처를 허용해야 합니다. 이미 실행 중인 Ollama는 종료한 뒤 실행합니다.

```sh
OLLAMA_ORIGINS="https://speckmaker-review.helloooo33.chatgpt.site,http://localhost:5173,http://127.0.0.1:5173" ollama serve
```

브라우저에서 로컬 네트워크 접근 권한을 요청하면 허용해야 합니다. 주소와 모델은 기기별 설정으로만 저장합니다. [Ollama 도구 호출 문서](https://docs.ollama.com/capabilities/tool-calling)와 [연결 FAQ](https://docs.ollama.com/faq#how-can-i-allow-additional-web-origins-to-access-ollama)를 참고하세요.

## 변경 이력과 버전

- 적용한 AI 변경마다 HTML 원본 전체를 R2에 보관하고, 변경 번호·작성자·요청·모델·시간을 D1에 저장합니다.
- **변경 이력 → 현재 버전 저장**에서 이름을 붙여 체크포인트를 만들 수 있습니다. 과거 변경에도 이름을 붙일 수 있습니다.
- 과거 변경을 미리 본 뒤 복원하면 새 변경으로 기록됩니다. 원본과 이전 이력을 삭제하거나 덮어쓰지 않습니다.
- 처음 올린 원본은 변경 #0이며 기존 업로드에도 처음 수정·버전 저장 시 원본 이력을 준비합니다.
- 파일의 변경 번호를 사용해 동시 수정 충돌을 막습니다. 요청 식별자로 중복 적용을 방지하며, 동시에 재시도해도 파일이 사라지지 않습니다.
- 이력은 한 번에 30개씩 불러오고 이전 변경을 추가로 볼 수 있습니다.

새 마이그레이션 `drizzle/0002_cooing_betty_ross.sql`도 로컬 환경에서 순서대로 한 번 적용해야 합니다. 배포 환경에서는 Sites가 적용합니다.

검증: 설치된 `qwen3.5:latest`로 실제 스트리밍 HTML 수정과 클릭 핸들러 보존, 배포 출처 CORS 응답을 확인했습니다. 저장 API로 원본 보관, AI 적용, 이름 있는 버전 저장, 복원 이력 추가, 과거 HTML 읽기, 오래된 수정 거절, 동시 요청 충돌, 동시 재시도 멱등성, 미완성 HTML 차단을 확인했습니다.

## 에이전트 회귀 테스트

```sh
npm run test:agent
npx tsc --noEmit
```

큰 압축 HTML의 범위 읽기·부분 교체, 불명확하거나 오래된 교체 거절, 스트리밍 도구 응답 복원, 실행 오류 재수정, 실패한 검사 조건의 재확인, 문맥 정리, 중단 시 원본 유지를 테스트합니다.

실제 Chromium과 로컬 `qwen3.5:latest`를 연결해 180,495바이트 HTML의 버튼 색상을 부분 수정했습니다. 전체 원본을 모델에 전송하지 않았고, 이 실행의 최대 단일 요청 크기는 18,994바이트였습니다. 실제 클릭 동작, 나머지 원본 보존, 변경 이력 한 건으로 적용, 이름 있는 버전 저장을 확인했습니다. 미리보기 검사의 버튼·CSS 조건, 문법 오류, Promise 오류, 네트워크 차단 및 중단 시 iframe 제거도 별도로 확인했습니다.
